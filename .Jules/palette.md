## 2025-07-19 - USSD Simulator Accessibility and Localization
**Learning:** Mockups and interactive simulators (like a USSD phone terminal) often use static non-semantic elements (like divs) for layout. Converting these to `<button>` elements with correct focus indicators and state attributes (`aria-pressed`) ensures screen reader and keyboard accessibility. Additionally, asynchronous updates in tech-logs/debug consoles should utilize `role="log"` and `aria-live="polite"` so screen reader users receive timely, non-disruptive feedback. Purely decorative elements (like blinking cursors) should be hidden with `aria-hidden="true"`.
**Action:** When designing mockups or simulator-style UIs, prioritize semantic elements over divs, implement centralized state lookup tables for localization, use dynamic aria-pressed indicators, and wrap dynamic terminal/log outputs with accessible aria-live log containers.
